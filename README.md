# Balance_Car

CH32V203 两轮自平衡小车工程，按 `micu平衡车插件版 V1.1` 原理图移植，并参考“平衡车第五讲”的姿态解算和串级控制思路实现。

> 本 README 是工程的代码导航和调试手册。后续修改模块、引脚、控制算法、显示内容或参数时，应同步更新这里，避免代码和说明不一致。

## 1. 当前实现状态

- 上电时 TB6612 `STBY=0`，电机保持断电。
- MPU6050 连续稳定约 2 秒后，自动计算陀螺仪零偏和车体直立零点。
- 校准成功后自动使能电机并进入平衡控制。
- 姿态环 200 Hz：MPU6050采样、互补滤波、角度 PD、电机输出。
- 速度环 20 Hz：编码器测速、速度 PI，当前目标速度为 0。
- 电机启动阶段有 1 秒软限幅，速度积分有防饱和限制。
- MPU6050连续通信失败3次，立即关闭电机。
- 相对直立角超过 `+/-45°` 后锁存跌倒故障，必须重新上电才能恢复。
- `main.c`中的 `g_balance_fall_protection_enabled` 控制45°保护：`1`启用，`0`关闭。
- 0.96英寸、128×64 OLED每200 ms刷新一次，两个页面每5秒切换。
- OLED未连接或初始化失败时，平衡控制仍可运行；显示不会阻塞控制逻辑。

## 3. 硬件引脚

- OLED软件I2C：`PB0=SCL`，`PB1=SDA`，7位地址 `0x3C`。
- MPU6050软件I2C：`PB6=SCL`，`PB7=SDA`，7位地址 `0x68`。
- 右编码器：`PA0/PA1 -> TIM2`。
- 左编码器：`PA6/PA7 -> TIM3`。
- TB6612左电机PWM：`PA8 -> TIM1_CH1/PWMA`。
- TB6612右电机PWM：`PA9 -> TIM1_CH2/PWMB`。
- TB6612左方向：`PB13=AIN1`，`PB14=AIN2`。
- TB6612右方向：`PA11=BIN1`，`PA10=BIN2`。
- TB6612使能：`PB15=STBY`。

注意：`PA9`已作为右电机PWM，当前工程没有启用模板中的USART1 TX，不能同时把PA9当串口发送脚使用。

## 4. 程序启动流程

```text
上电
  ├─ 初始化系统时钟和Delay
  ├─ 尝试初始化OLED
  ├─ Motor_Init，保持STBY=0
  ├─ Encoder_Init并清零
  ├─ MPU6050_Init
  │    └─ 失败：进入SENSOR_ERROR，电机保持断电
  ├─ 启动TIM4的200 Hz中断
  ├─ 保持车体静止，采集400个校准样本
  │    ├─ 姿态或角速度不稳定：校准计数重新开始
  │    └─ 校准成功：计算直立零点和陀螺零偏
  ├─ TB6612 STBY=1，进入RUNNING
  └─ 主循环只负责OLED显示，实时控制在TIM4中断中执行
```

平衡状态 `BalanceState` 的含义：

- `BOOT`：初始化尚未完成。
- `CALIBRATING`：等待车体稳定并采集零点。
- `RUNNING`：姿态环和速度环正在工作。
- `FALLEN`：倾角超过45°，电机已锁定关闭。
- `SENSOR_ERROR`：MPU6050初始化失败或连续通信失败。

## 5. 一次200 Hz控制周期

`TIM4_IRQHandler()`每5 ms调用一次 `Balance_ControlStep()`，执行顺序如下：

1. 从MPU6050一次读取14字节，获得三轴加速度、温度和三轴角速度。
2. 由X、Z轴加速度计算车体俯仰角。
3. 校准阶段累计直立角和Y轴陀螺仪零偏。
4. 运行阶段计算相对加速度角和校准后的角速度。
5. 用互补滤波得到最终控制角 `pitch_deg`。
6. 判断融合角是否超过45°，超过则紧急停止。
7. 每10个控制周期读取一次编码器，即速度环每50 ms执行一次。
8. 速度PI输出修正量，角度PD输出电机控制量。
9. 经过软启动限幅、方向修正后输出左右电机PWM。

OLED刷新位于主循环，不在TIM4中断里。这样完整刷新128×64显存时，不会把显示传输时间加入控制中断。

## 6. 姿态角计算

MPU6050当前配置为加速度计 `+/-2g`、陀螺仪 `+/-500°/s`。

```text
accel_angle = -atan2(ax, az) × 180 / π
relative_accel_angle = accel_angle - upright_angle
gyro_rate = gy / 65.5 - gyro_bias
gyro_predicted_angle = pitch + gyro_rate × 0.005
pitch = 0.985 × gyro_predicted_angle
      + 0.015 × relative_accel_angle
```

含义：短时间快速变化主要相信陀螺仪，长时间零点主要由加速度计修正。

MPU6050原始数据换算关系：

- 加速度计：±2g量程时，约 `16384 LSB = 1g`。
- 陀螺仪：±500°/s量程时，`65.5 LSB = 1°/s`。
- 温度：`temperature = raw / 340 + 36.53°C`。
- `SMPLRT_DIV=4`且DLPF开启，采样率为 `1kHz/(1+4)=200 Hz`。

### 6.1 车头方向和角度正负约定

以用户提供的实车照片为准，**照片中面向相机的一侧定义为车头/前方**，远离相机的一侧定义为车尾/后方。

本工程真正参与平衡控制的是相对直立角：

```text
直立控制角 = 0°
向前倾角度 = 相对直立位置向车头方向倾斜的角度
向后倾角度 = 相对直立位置向车尾方向倾斜的角度
```

需要区分OLED上的几个数值：

- `ACC ABS`是MPU6050相对自身坐标计算出的绝对安装角。传感器焊接存在偏差时，车体直立也可能显示 `+2.3°` 或 `-3.1°`，这不是故障。
- `ZERO`是上电时车体保持直立后，程序记录的 `ACC ABS`平均值。
- `ACC REL = ACC ABS - ZERO`，所以校准位置理论上为 `0°`。
- `GYR RATE`是正在倾倒的角速度，不是车体当前角度。静止保持在任意倾角时，它都应逐渐回到约 `0°/s`。
- `GYR PRED`是根据当前融合角和5 ms角速度预测出的下一时刻角度。
- `FUSED`是最终融合角，也是45°保护和角度PD使用的关键角度。

当前代码采用：

```text
ACC ABS = -atan2(AX, AZ) × 180 / π
```

因此从数学定义看，**车体顶部朝MPU6050板上的 `+X` 箭头方向倾斜时为正角，朝 `-X` 方向倾斜时为负角**。

照片无法清楚看到MPU6050模块上的X轴丝印，所以不能只凭照片保证“向车头倾斜”在当前安装下究竟是正数还是负数。必须断开电机动力，完成一次以下检查：

1. 车体按正常姿态直立，完成校准，此时 `ACC REL≈0°`、`FUSED≈0°`。
2. 将车体顶部缓慢向照片中的相机方向，也就是车头方向倾斜约10°。
3. 如果 `ACC REL`和`FUSED`变为约 `+10°`，则当前安装是“前倾为正、后倾为负”。
4. 如果两者变为约 `-10°`，则当前安装是“前倾为负、后倾为正”。
5. 倾斜过程中，`GYR RATE`应与角度变化方向同号；保持不动后应回到约0。

无论采用哪一种正负号，只要加速度角、陀螺角速度和电机追赶方向相互一致，控制都可以工作。为了方便理解和后续调试，建议最终统一成“前倾为正、后倾为负”。

### 6.2 各种姿态的理论角度

以下先采用推荐约定：**前倾为正，后倾为负**。如果实测前倾为负，则下面所有前后方向的正负号整体对调，角度绝对值不变。

- 正常直立：`ACC REL≈0°`，`FUSED≈0°`；`ACC ABS≈ZERO`。
- 向前轻微倾斜5°：`ACC REL≈+5°`，稳定后 `FUSED≈+5°`。
- 向前倾斜10°：`ACC REL≈+10°`，稳定后 `FUSED≈+10°`。
- 向前倾斜30°：`ACC REL≈+30°`，稳定后 `FUSED≈+30°`。
- 向前倾斜45°：`FUSED≈+45°`，达到当前跌倒保护边界。
- 向后轻微倾斜5°：`ACC REL≈-5°`，稳定后 `FUSED≈-5°`。
- 向后倾斜30°：`ACC REL≈-30°`，稳定后 `FUSED≈-30°`。
- 向后倾斜45°：`FUSED≈-45°`，达到当前跌倒保护边界。
- 向前完全平倒，车体顶部指向车头：理论值约 `+90°`。
- 向后完全平倒，车体顶部指向车尾：理论值约 `-90°`。
- 上下完全倒置：理论值接近 `+180°` 或 `-180°`；`atan2`会在这里发生正负180°跳变。
- 小幅向左或向右侧倾：这是横滚角，不是当前控制的俯仰角，`FUSED`理论上仍接近0°。
- 侧倾接近90°：`AZ`接近0，当前俯仰公式会变得敏感，显示可能受噪声影响。
- 水平原地转向：这是偏航运动，理想情况下俯仰角仍接近0°，主要表现为 `GZ`变化。

45°保护使用的是 `FUSED`相对角，而不是 `ACC ABS`。因此即使直立时传感器绝对安装角为 `-3°`，只要校准得到 `ZERO=-3°`，车体前倾45°时融合相对角仍约为 `+45°`。

保护开启时，一旦越过45°程序就进入 `FALLEN` 并停止继续更新姿态，所以OLED通常停留在触发保护附近，而不会继续显示到90°或180°。如需观察完整角度范围，应断开电机动力或架空车轮，再把 `main.c` 中的倾角保护标志临时设为 `0U`。

### 6.3 静止时原始加速度的理论依据

假设MPU6050的 `+X` 指向车头、`+Z`在直立时指向重力反作用方向，并忽略运动加速度，则前倾角为 `θ` 时：

```text
AX ≈ -16384 × sin(θ)
AZ ≈ +16384 × cos(θ)
ACC ABS = -atan2(AX, AZ) ≈ θ
```

几个典型值：

- 直立0°：`AX≈0`，`AZ≈+16384`。
- 前倾30°：`AX≈-8192`，`AZ≈+14189`。
- 前倾45°：`AX≈-11585`，`AZ≈+11585`。
- 前倾90°：`AX≈-16384`，`AZ≈0`。
- 后倾30°：`AX≈+8192`，`AZ≈+14189`。
- 后倾90°：`AX≈+16384`，`AZ≈0`。
- 倒置180°：`AX≈0`，`AZ≈-16384`。

这些关系只在静止或缓慢倾斜时成立。车辆突然加速、刹车或轮胎撞击时，加速度计同时测到运动加速度，`ACC ABS/ACC REL`会短暂偏离真实角度；互补滤波正是用陀螺仪来减小这种影响。

### 6.4 横滚角和偏航角

当前平衡算法只计算前后俯仰角 `Pitch`，没有把横滚和偏航角用于控制。

- 横滚角 `Roll`可近似由 `atan2(AY, AZ)`计算，但正负号仍取决于模块安装方向。
- 偏航角 `Yaw`只能由 `GZ`积分得到相对变化量。
- MPU6050没有磁力计，静止时无法仅靠重力确定绝对偏航方向；对 `GZ`积分会随时间漂移。
- 两轮平衡车的核心控制量是前后俯仰角，左右侧倾通常由机械结构限制，转向则依靠左右轮差速控制。

## 7. 控制算法

当前使用“速度PI + 角度PD”的串级控制思路。

```text
left_speed  = left_count  / (408.173 × 0.05)
right_speed = right_count / (408.173 × 0.05)
average_speed = 0.5 × (left_speed + right_speed)

speed_error = 0 - average_speed
speed_integral += speed_error × 0.05
speed_output = Speed_Kp × speed_error
             + Speed_Ki × speed_integral

angle_error = 0 - pitch
balance_output = Angle_Kp × angle_error
               - Angle_Kd × gyro_rate

total_output = balance_output + speed_output
left_pwm  = limit(total_output × left_motor_sign)
right_pwm = limit(total_output × right_motor_sign)
```

目前没有角度积分项。平衡车角度环通常先用PD，积分容易在车体被手扶、卡住或倒地时积累过大输出。

## 8. 重要参数

主要控制参数集中在 `User/Hardware/balance_config.h`。

控制周期：

- `BALANCE_CONTROL_HZ = 200`：角度控制频率200 Hz。
- `BALANCE_CONTROL_DT = 0.005`：角度控制周期5 ms。
- `BALANCE_SPEED_DIVIDER = 10`：每10次姿态环执行一次速度环。
- `BALANCE_SPEED_DT = 0.050`：速度控制周期50 ms，即20 Hz。

上电校准：

- `BALANCE_CALIBRATION_SAMPLES = 400`：连续400个稳定样本，约2秒。
- `BALANCE_CALIBRATION_MAX_ANGLE_DEG = 15.0`：校准时允许的最大绝对安装角。
- `BALANCE_CALIBRATION_MAX_GYRO_DPS = 5.0`：校准时允许的最大角速度。
- 车体运动超出任一限制，400次稳定计数会清零重来。

滤波与保护：

- `BALANCE_COMPLEMENTARY_ALPHA = 0.985`：陀螺预测角权重。
- `BALANCE_FALL_ANGLE_DEG = 45.0`：相对直立角超过该值立即断电。
- `SENSOR_FAILURE_LIMIT = 3`：连续读取失败3次后断电，定义在 `balance.c`。
- `g_balance_fall_protection_enabled = 1`：倾角保护总开关，定义在 `main.c`；改为 `0` 后重新编译即可关闭。

角度PD初值：

- `BALANCE_ANGLE_KP = 22.0`：倾角误差放大倍数。
- `BALANCE_ANGLE_KD = 0.90`：角速度阻尼，主要抑制快速振荡。

速度PI初值：

- `BALANCE_SPEED_KP = 70.0`。
- `BALANCE_SPEED_KI = 25.0`。
- `BALANCE_SPEED_INTEGRAL_LIMIT = 8.0`：积分绝对值限制。
- `BALANCE_SPEED_OUTPUT_LIMIT = 300.0`：速度环最大修正输出。

PWM与电机：

- `BALANCE_START_PWM_LIMIT = 300`：刚启动时最大控制量为满量程的30%。
- `BALANCE_FULL_PWM_LIMIT = 1000`：正常运行最大控制量。
- `BALANCE_SOFT_START_TICKS = 200`：约1秒内从300线性放宽到1000。
- `MOTOR_COMMAND_MAX = 1000`：`Motor_SetPWM()`输入范围为-1000～1000。
- `MOTOR_DEAD_ZONE = 100`：非零命令加入约10%的启动死区补偿。
- `MOTOR_TIMER_PERIOD = 4799`：96 MHz定时器时钟下产生约20 kHz PWM。

编码器与方向：

- `BALANCE_ENCODER_COUNTS_PER_REV = 408.173`，来源为 `11 × 4 × 9.27666`。
- `BALANCE_LEFT_MOTOR_SIGN = 1`，`BALANCE_RIGHT_MOTOR_SIGN = 1`。
- `BALANCE_LEFT_ENCODER_SIGN = -1`，`BALANCE_RIGHT_ENCODER_SIGN = -1`。
- 方向不正确时优先只修改这四个符号，不要同时改PID正负号和电机底层逻辑。

以上PID值是安全起调初值，不是实车最终值。电池电压、轮径、电机、减速比、车体重量和重心变化后都需要重新调节。

## 9. OLED页面

OLED使用6×8字体，共8行，每行最多21个ASCII字符。

显示调度参数定义在 `User/main.c`：

- `DISPLAY_REFRESH_TICKS = 40`：40个5 ms周期，即每200 ms刷新。
- `DISPLAY_PAGE_TICKS = 1000`：1000个5 ms周期，即每5秒切换页面。

第一页 `MPU6050 RAW 1/2`：

- `AX/AY/AZ`：三轴加速度原始值。
- `GX/GY/GZ`：三轴陀螺仪原始值。
- `ID:68 OK`：已识别到MPU6050；通信故障时显示 `ID:ERROR`。
- `TEMP`：芯片内部温度。
- `ACC:2G`、`GYRO:500DPS`：当前量程。
- `STATE`：平衡状态。

第二页 `BALANCE ANGLE 2/2`：

- `ACC ABS`：加速度计计算的绝对安装角。
- `ACC REL`：减去校准直立零点后的加速度角。
- `GYR RATE`：扣除零偏后的Y轴角速度。
- `GYR PRED`：陀螺仪对下一时刻姿态的预测角。
- `FUSED`：互补滤波输出，也是平衡PD实际使用的角度。
- `ZERO`：上电校准得到的直立绝对角。
- `LIM`：跌倒保护阈值45°。

显示过程先修改OLED内存缓冲区，最后统一调用一次 `OLED_Refresh()`。`oled_printf(row, column, ...)`可用于简单选行、选列显示；连续多行刷新优先使用 `OLED_Print()`后统一刷新。

### 9.1 如何判断MPU6050读取正常

当前驱动已经完成以下通信检查：

- 初始化时读取 `WHO_AM_I`，必须等于 `0x68`。
- 每次发送设备地址、寄存器地址和配置值时检查I2C应答。
- 上电时如果SDA被拉低，软件I2C发送最多9个SCL脉冲尝试恢复总线。
- 每个控制周期从 `0x3B` 开始连续读取14字节，保证六轴和温度来自同一组样本。
- 连续读取失败3次后进入 `SENSOR_ERROR` 并关闭电机。

静止直立时可按下面的范围判断数据是否合理：

- `ID:68 OK`应持续正常；出现 `ID:ERROR`需要检查PB6、PB7、电源和地线。
- `AX`理论上接近0；因为安装误差，存在几百到几千计数偏差也可能正常。
- `AZ`在当前安装假设下应接近 `+16384`，明显接近 `-16384`说明Z轴安装方向相反。
- `sqrt(AX²+AY²+AZ²)`应接近16384；静止时大致处于14000～19000可作为初步判断范围。
- 原始 `GX/GY/GZ`不一定严格为0，存在零偏是正常现象。
- 校准完成后静止时 `GYR RATE`应接近 `0°/s`，小幅抖动正常。
- 室温环境下 `TEMP`通常应是连续、缓慢变化的合理数值，不应突然跳到极端温度。
- 缓慢前后倾斜时，`AX/AZ`应连续变化，`ACC REL`和`FUSED`应同方向且数值接近。
- 保持在固定倾角时，`GYR RATE`应回到约0，而 `ACC REL/FUSED`应保持在该倾角附近。

以下现象通常表示读取异常：

- 六轴长期全部为0、全部为-1或固定不变。
- 静止不动时数值大范围随机跳变。
- 轻触线材就进入 `MPU ERROR`。
- `ACC REL`与 `FUSED`长期方向相反。
- 前倾过程中 `ACC REL`增加，但 `GYR RATE`持续给出相反方向的动态变化。

I2C本身没有为这14字节数据提供CRC，当前代码也没有做加速度模长和突变值拒绝。因此“通信函数返回成功”只能证明设备有应答，不能完全证明每个样本都物理合理。实车控制前仍必须完成以上静态和缓慢倾斜测试。

## 10. 安全保护

以下任意条件会使PWM清零、方向脚拉低并将TB6612的 `STBY` 拉低：

- MPU6050初始化失败。
- MPU6050连续读取失败3次。
- 融合角绝对值超过45°。
- 程序主动调用 `Motor_EmergencyStop()`。

`FALLEN`和`SENSOR_ERROR`是锁定状态，当前设计需要重新上电复位，避免倒地后电机突然自行恢复。

倾角保护开关位于 `User/main.c`：

```c
const uint8_t g_balance_fall_protection_enabled = 1U;
```

- `1U`：启用 `BALANCE_FALL_ANGLE_DEG` 阈值保护。
- `0U`：关闭倾角阈值检查，但MPU6050通信故障保护仍然有效。
- 关闭后车辆倒地时电机仍可能继续输出，只能在架空车轮或断开电机动力电源的调试环境中使用。
- 修改该值后必须重新编译并重新烧录。

## 11. 首次上电调试顺序

1. 先断开电机动力电源，或把车架牢固架空让轮胎离地。
2. 上电后观察OLED第一页，确认MPU6050六轴数据会随姿态变化。
3. 保持车体直立静止，等待 `STATE` 从 `CALIBRATING` 变为 `BALANCING`。
4. 观察第二页：静止时 `GYR RATE` 应接近0，直立时 `ACC REL` 和 `FUSED` 应接近0。
5. 向前倾斜车体，记录 `FUSED` 的正负号；轮胎必须向同一方向追赶车体。
6. 如果轮子追赶方向错误，立即断电，只调整左右 `MOTOR_SIGN`。
7. 单独验证编码器正反方向；正方向转动时测速应为正，否则调整对应 `ENCODER_SIGN`。
8. 方向全部正确后，先调角度 `Kp/Kd`，最后再调速度 `Kp/Ki`。
9. 未完成架空方向测试前，不要直接把小车放到地面运行。

## 12. PID调试原则

建议先临时把速度环增益设为0，只调角度PD：

1. 从较小的 `BALANCE_ANGLE_KP` 开始，确认电机追赶方向正确。
2. 缓慢增加 `Kp`，直到车体有明显扶正能力，但可能快速振荡。
3. 增加 `Kd` 抑制快速振荡和过冲。
4. 角度环能短暂站立后，再恢复速度环。
5. 调整速度 `Kp` 减少持续移动，再小幅增加 `Ki` 消除慢速漂移。
6. 每次只改一个参数并记录现象，不要同时修改多个增益和方向符号。

常见现象：

- 轻微倾斜后轮子反向跑：电机方向符号错误，不是Kp太小。
- 高频快速抖动：角度Kp偏大或Kd偏小。
- 反应迟缓、扶不起来：角度Kp偏小、电机死区过大或供电不足。
- 能直立但持续前后慢跑：速度环需要调节，或机械直立零点不准确。
- 大幅度慢摆：速度环Kp/Ki偏大，或角度环阻尼不足。

## 15. 目标分层架构（规划，尚未完成重构）

当前版本已经可以编译运行，但 `Hardware/balance.c` 同时承担状态机、姿态融合、控制器和安全保护，设备驱动中也仍有固定引脚与CH32外设依赖。后续重构目标采用以下单向分层：

```text
业务/应用层
  App：启动编排、BalanceApp状态机、OLED页面策略
        ↓
服务/中间件层
  Services：姿态估计、角度PD、速度PI、安全监控、遥测快照
        ↓
外设驱动层
  Drivers：MPU6050、SSD1306、TB6612、编码器设备协议
        ↓
硬件抽象层
  BSP：GPIO、PWM、控制定时器、编码器定时器、软件I2C端口
        ↓
启动/内核层
  Startup/Core：复位入口、系统时钟、异常与RISC-V内核支持
```

依赖约束：

- 上层只能调用下一层公开接口，禁止下层回调或包含业务模块。
- 只有启动层和BSP可以包含 `ch32v20x.h`、访问GPIO/TIM寄存器。
- MPU6050、SSD1306等驱动通过注入的I2C接口访问总线，不固定PB6/PB7或PB0/PB1。
- 姿态估计和控制器只接收普通C数据结构，不依赖MCU头文件，可在PC端做单元测试。
- ISR只维持固定控制节拍，不刷新OLED、不格式化字符串。

计划拆分：

- `main.c`拆成 `App/app_main.c` 与 `App/ui_pages.c`。
- `balance.c`拆成 `balance_app.c`、`attitude_estimator.c`、`balance_controller.c`和`safety_monitor.c`。
- `motor.c`拆成TB6612设备语义与BSP PWM/GPIO实现。
- `oled.c`拆成SSD1306显存驱动与显示页面服务。
- `soft_i2c.c`下沉BSP，并向驱动层提供不包含CH32类型的 `I2cBus` 接口。

目标配置文件：

- `Config/board_config.h`：引脚、端口和定时器映射。
- `Config/sensor_config.h`：MPU地址、量程、采样率、DLPF和轴方向。
- `Config/control_config.h`：控制频率、PID、编码器换算和方向符号。
- `Config/safety_config.h`：45°保护、传感器失败次数和校准稳定条件。
- `Config/motor_config.h`：PWM频率、命令范围、死区和软启动。
- `Config/ui_config.h`：OLED地址、刷新周期和页面切换周期。

建议迁移顺序是：冻结当前可运行固件 → 提取纯算法 → 注入I2C接口 → 下沉板级寄存器操作 → 建立应用状态机 → 架空实车回归。每一步都保持工程可编译、可回退，避免一次性大改导致无法定位硬件问题。
